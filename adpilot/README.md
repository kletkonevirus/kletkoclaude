# AdPilot — операционный контроллер рекламы (MVP-прототип)

Запускает и контролирует рекламные кампании автоправилами, **гейтит расход реальной
пропускной способностью доставки** (курьеры/кухня) и сигналит об аномалиях трафика.

Прототип работает **сегодня на моках** — без доступов к API площадок и без внешних
зависимостей (только стандартная библиотека Python 3.11+). Реальные кабинеты
Meta/Google/TikTok подключаются позже за тот же интерфейс, не трогая движок.

## Запуск

```bash
cd adpilot
python run.py                      # http://127.0.0.1:8787, тик каждые 3 сек, откроет браузер
python run.py --port 9000 --interval 1 --no-open
```

Откроется веб-приложение с пятью разделами (сайдбар слева):

- **Обзор** — KPI (кабинеты, кампании, расход, заказы, CPA, ROAS), загрузка доставки по
  городам, очередь подтверждений (Подтвердить/Отклонить), лента сигналов, аудит автодействий.
- **Интеграции** — подключение/отключение рекламных кабинетов Meta/Google/TikTok.
  (Прототип мокирует подключение; в проде здесь OAuth площадки.)
- **Кампании** — управление: пауза/старт, изменение бюджета и целевых CPA/ROAS.
- **Правила** — включение/выключение автоправил, настройка порогов и политики
  «авто-исполнение / только предложение».
- **Креативы** — загрузка креатива и привязка к кампании (мок asset id).

При первом запуске подключён демо-кабинет Meta, чтобы сразу были данные.

## Что демонстрирует прототип

- **Мультиплатформенность** — Meta / Google / TikTok за единым адаптером (сейчас `MockAdapter`).
- **Операционный пейсинг** — при перегрузе доставки в городе бюджет режется пропорционально
  (Almaty в демо перегружен → throttle), при критическом перегрузе → пауза с авто-восстановлением.
- **Стоп-лосс по CPA** — кампании с CPA выше 1.8× таргета уходят в паузу (остаётся человеку).
- **Разгон победителей** — при ROAS ≥ 1.25× таргета и свободной доставке предлагается +20%
  бюджета — но только **через подтверждение человека**.
- **Детектор аномалий** — всплеск расхода / обвал конверсии по z-score.

## Ключевой принцип безопасности: асимметричная автономность

| Направление | Пример | Кто решает |
|---|---|---|
| Снижает / не повышает расход | пауза, throttle, стоп-лосс, возврат к плановому бюджету | **автомат** |
| Повышает расход выше плана | +20% бюджета, разгон | **человек** (очередь подтверждений) |

Движок автоправил — **детерминированный код, без LLM**: предсказуемо, быстро, полностью
аудируемо. LLM (агент `digital-ads-strategist`) — это слой аналитика/советника поверх, а не
исполнитель, трогающий деньги.

## Архитектура

```
run.py                энтрипоинт: фоновый тик-луп + веб-сервер + демо-кабинет
adpilot/
  models.py           доменная модель (Account, Campaign, Metrics, Action, RuleConfig, Creative…)
  store.py            потокобезопасное состояние (in-memory; в проде — БД + аудит-лог)
  adapters.py         PlatformAdapter (контракт) + MockAdapter; сюда придут Meta/Google/TikTok
  service.py          управление: connect/disconnect кабинетов, пауза/бюджет/таргеты, креативы
  signals.py          OperationsSignal (курьеры UTR из data/) + AnomalyDetector
  rules.py            RulesEngine + правила + конфиги; асимметрия, кулдауны, дедуп
  tick.py             оркестрация цикла: pull → аномалии → накопление → правила
  server.py           статика SPA + REST API (интеграции/кампании/правила/креативы/подтверждения)
  web/                фронтенд (index.html, styles.css, app.js) — vanilla JS, без сборки
data/
  couriers_by_day.csv реальные данные курьеров (baseline загрузки для пейсинга)
```

## Что мок, а что реально сейчас

- **Мок:** метрики площадок (spend/orders/revenue), сами кабинеты, заливка креативов.
- **Реально:** baseline загрузки курьеров берётся из `data/couriers_by_day.csv` (в этом публичном пакете — СИНТЕТИЧЕСКИЕ данные, не боевые)
  (медиана «среднее заказов на курьера» → цель с 15% запасом). Текущая загрузка по городам
  пока симулируется (нет живого per-city реалтайма).
- **Готов реальный адаптер Meta** (`adapters_meta.py`) — активируется, как только заданы креды.

## Подключение реального кабинета Meta

1. Получить креды (подробно — `docs/API_SETUP.md`): Meta app + Marketing API,
   **System User token** (`ads_read` + `ads_management`), id кабинета `act_…`.
2. `cp .env.example .env` и вписать `META_ACCESS_TOKEN` и `META_AD_ACCOUNT_ID`
   (файл `.env` в `.gitignore` — не коммитится, в чат не вставлять).
3. Проверить связь (только чтение, ничего не меняет):
   ```
   python verify_meta.py
   ```
4. Запустить как обычно — для площадки meta автоматически используется живой адаптер:
   ```
   python run.py
   ```

Без кредов всё работает на моках (`MockAdapter`). Адаптер покрыт офлайн-тестом
`tools/test_meta_offline.py` (проверяет запросы/парсинг без токена).
