# AdPilot × Яндекс.Директ — передача задачи

Этот документ самодостаточен. Прочитав только его + `adpilot/adapters_yandex.py`,
можно сделать всю работу, **не изучая остальной код**. Не нужно исследовать репозиторий целиком.

---

## 1. Что уже есть (контекст в 10 строк)

**AdPilot** — операционный контроллер рекламы Choco (фуд-доставка, Казахстан).
Чистый Python 3.11+ stdlib, ноль зависимостей, запуск `python run.py` → дашборд на `localhost:8787`.

Устройство:
- `adpilot/adapters.py` — интерфейс `PlatformAdapter` + `MockAdapter`. **Движок правил знает только этот интерфейс** и не знает, какая площадка за ним.
- `adpilot/adapters_meta.py` — готовый живой адаптер Meta (Graph API через `urllib`). **Эталон для копирования.**
- `adpilot/rules.py` — детерминированный движок автоправил.
- `adpilot/signals.py` — операционный пейсинг (гейтит расход загрузкой курьеров) + детект аномалий.
- `adpilot/tick.py`, `service.py`, `server.py`, `store.py` — цикл, сервисный слой, веб-UI, хранилище в памяти.
- `config.py` — читает `.env` без зависимостей.

**Задача:** добавить Яндекс.Директ как ещё одну площадку за тем же интерфейсом.
Движок, правила, пейсинг, UI **не меняются**. Меняется только новый адаптер + 4 строки регистрации.

### Два архитектурных правила проекта — не нарушать

1. **Асимметричная автономность.** Снижение бюджета / пауза / throttle / минус-фразы — автомат.
   Повышение бюджета, разгон, расширение таргета — **только через подтверждение человека.**
2. **LLM не в контуре денег.** Движок автоправил — детерминированный код. Никаких вызовов модели
   в пути принятия решения о расходе. Модель — только слой аналитики/советника сверху.

## 2. Контракт, который надо реализовать

Из `adpilot/adapters.py`:

```python
class PlatformAdapter(ABC):
    platform: Platform

    def create_campaigns(self, account: Account) -> list[Campaign]:
        """Подтянуть кампании подключённого кабинета."""

    def refresh_metrics(self, campaign: Campaign) -> Metrics:
        """Метрики за ОДНО последнее окно (ДЕЛЬТА, не накопленные)."""

    def set_status(self, campaign: Campaign, status: EntityStatus) -> None: ...
    def set_budget(self, campaign: Campaign, budget: float) -> None: ...
    def upload_creative(self, campaign: Campaign, path: str, meta: dict) -> str: ...
```

`Metrics` — поля `spend, impressions, clicks, orders, revenue` (числа).
`EntityStatus` — `ACTIVE` / `PAUSED`. `Campaign.id` — id на стороне площадки (строка).

> ⚠️ **Дельта, а не накопленное.** Отчёты Директа за день возвращают накопленные значения.
> `MetaAdapter` решает это телескопированием: хранит прошлый снимок в `self._last[campaign.id]`
> и отдаёт разницу. **Скопировать этот приём** — иначе движок посчитает расход кратно завышенным.

## 3. Соответствие: контракт → API Директа v5

Базовый URL: `https://api.direct.yandex.com/json/v5/{service}`
Песочница: `https://api-sandbox.direct.yandex.com/json/v5/{service}`

| Метод адаптера | Сервис / метод Директа |
|---|---|
| `create_campaigns` | `campaigns` → `get` (поля `Id, Name, State, Status, DailyBudget`) |
| `refresh_metrics` | `reports` → `ReportDefinition` (TSV) |
| `set_status(PAUSED)` | `campaigns` → `suspend` |
| `set_status(ACTIVE)` | `campaigns` → `resume` |
| `set_budget` | `campaigns` → `update` (поле `DailyBudget.Amount`) |
| `upload_creative` | `adimages` → `add` (base64), вернуть `AdImageHash` |

Все запросы — `POST` с телом `{"method": "...", "params": {...}}`.

Заголовки:
```
Authorization: Bearer <OAuth-токен>
Accept-Language: ru
Client-Login: <логин клиента>     # только для агентских аккаунтов, иначе не передавать
Content-Type: application/json; charset=utf-8
```

## 4. Доступ (делает владелец аккаунта, не исполнитель)

1. Зарегистрировать приложение в кабинете Яндекс ID → вкладка «Приложения».
2. В настройках приложения, раздел «API Директа» → **«Запросить доступ»**.
   Одобрение обычно **менее часа** (в отличие от Meta App Review — недели).
3. Получить OAuth-токен по стандартному flow, положить в `.env`.

Секреты в код не попадают. `.env` в `.gitignore`. Исполнитель к токену не прикасается —
владелец вставляет его сам.

`.env`:
```
YANDEX_DIRECT_TOKEN=...
YANDEX_DIRECT_LOGIN=...        # опционально, только для агентского доступа
YANDEX_DIRECT_SANDBOX=1        # 1 = песочница (по умолчанию для первой отладки)
YANDEX_CURRENCY_MICRO=1000000
```

## 5. Пять грабель Директа (главное в этом документе)

1. **Деньги в микро-единицах: ×1 000 000.** У Meta минорные единицы ×100 — легко скопировать
   константу и получить ошибку в 10 000 раз на бюджете в KZT. Либо делить на `1e6` при чтении
   и умножать при записи, либо передавать заголовок `returnMoneyInMicros: false` в отчётах —
   **но выбрать одно и то же поведение для чтения и записи.** Это дыра №1.

2. **Квота в баллах (points), а не в запросах.** Суточный лимит операций зависит от расхода
   аккаунта: маленький аккаунт = мало баллов. Дефолтный тик AdPilot — 3 секунды; **на живом
   Директе так опрашивать нельзя, баллы сгорят за минуты.** Нужно:
   - отдельный интервал опроса для Директа (минуты, не секунды);
   - читать из ответа `Units` (в заголовке `Units: взято/осталось/лимит`), при исчерпании — бэкофф;
   - батчить: один `reports`-запрос сразу на все кампании (`FieldNames: [CampaignId, ...]`),
     а не по кампании отдельно.

3. **Отчёты асинхронные.** `reports` может ответить `HTTP 201/202` + заголовок `retryIn` —
   отчёт ещё готовится, надо повторить запрос позже. Синхронный режим включается заголовком
   `processingMode: online`, но он работает только для маленьких отчётов. Тело ответа — **TSV,
   не JSON.** Ставить `skipReportHeader: true` и `skipReportSummary: true`, чтобы парсить проще.

4. **Конверсии Директа ≠ заказы Choco.** Директ считает цели Метрики. Реальный фуд-заказ живёт
   в DWH (мини-апп «Еда» в супер-аппе Freedom, инсталлы приходят фидом AppsFlyer супер-аппа).
   Поэтому: **`spend/impressions/clicks` берём из Директа, а `orders/revenue` сшиваем с данными
   Choco по кампании/городу.** Строить правила на конверсиях одного Директа — значит
   оптимизировать не тот KPI. На первом этапе допустимо заполнять `orders/revenue` из целей
   Метрики, но пометить в UI как «конверсии площадки, не заказы» и не включать по ним авто-разгон.

5. **Города.** Активный периметр — **Актау, Костанай, Усть-Каменогорск.** Алматы в текущий
   периметр не входит. `MetaAdapter._parse_city` вытаскивает город из имени кампании по списку
   `KNOWN_CITIES` — для Директа список нужен свой (латиница + кириллица: `Aktau/Актау`,
   `Kostanay/Костанай`, `Oskemen/UKG/Усть-Каменогорск`).

## 6. Уникальная ценность Директа: то, чего нет у Meta

У Директа есть уровень, которого нет в текущем движке, и он даёт самую быструю экономию.
Всё перечисленное — **«снижение», значит автомат, подтверждение человека не требуется.**

| Возможность | API | Правило |
|---|---|---|
| Мусорные поисковые запросы | отчёт `SEARCH_QUERY_PERFORMANCE_REPORT` → `keywords`/`adgroups` → `update` (`NegativeKeywords`) | расход > X и 0 конверсий за N дней → в минус-фразы |
| Площадки РСЯ | отчёт по `Placement` → `campaigns.update` (`ExcludedSites`) | CPA площадки > 2× таргета → исключить |
| Ставки на уровне фраз | `keywordbids` → `set` | понижать ставку убыточных фраз, а не рубить кампанию |
| Автотаргетинг | `adgroups` → `update` | контролировать отдельно: умеет тихо съедать бюджет |

Это **второй этап**. Сначала — базовый контракт (раздел 2), он закрывает пейсинг и стоп-лоссы.

## 7. Порядок работ

### Этап 0 — read-only (первое, что нужно сделать; ~один вечер)
1. Взять скелет `adpilot/adapters_yandex.py` — там уже есть транспорт, клиент, заголовки,
   разбор баллов и заготовки методов с TODO. Реализовать `create_campaigns` + `refresh_metrics`.
2. Транспорт **инъектируется** (параметр `transport=`), как в `adapters_meta.py` → офлайн-тест
   на замоканных ответах, без живого токена. Образец: `tools/test_meta_offline.py`.
   Сделать по образцу `tools/test_yandex_offline.py`.
3. Регистрация (ровно 4 правки, все точечные):

```python
# adpilot/models.py — в enum Platform
YANDEX = "yandex"

# adpilot/adapters.py — если нужен мок Директа, добавить ключ в CPM
CPM = {"meta": 2600, "google": 3200, "tiktok": 2100, "yandex": 1800}
# и в MockAdapter.create_campaigns → base_cpa добавить "yandex": 800

# adpilot/config.py — по образцу meta_config()
def yandex_config() -> dict | None: ...

# run.py — по образцу блока Meta (строки ~45-48 и ~55-62)
if yandex_cfg:
    from adpilot.adapters_yandex import YandexDirectAdapter
    adapters[Platform.YANDEX.value] = YandexDirectAdapter(**yandex_cfg)
```

4. Живая read-only проверка — скрипт `verify_yandex.py` по образцу существующего
   `verify_meta.py` (ничего не меняет в кабинете, только печатает кампании и метрики).

### Этап 1 — write (только после того, как read-only работает)
5. `set_status` / `set_budget` — **сначала отладить в песочнице** (`YANDEX_DIRECT_SANDBOX=1`).
6. Проверить, что пейсинг по курьерам (`signals.py`) корректно гейтит расход Директа.

### Этап 2 — специфика Директа
7. Минус-фразы по поисковым запросам, исключение площадок РСЯ (раздел 6).

## 8. Definition of done

- [ ] `python run.py` без кред Директа работает ровно как раньше (моки, ничего не сломано).
- [ ] С кредами — в UI появляется кабинет Директа с живыми кампаниями и метриками.
- [ ] `refresh_metrics` отдаёт **дельту**; суточный расход в UI совпадает с расходом в кабинете
      Директа (±копейки). Это ключевая проверка на грабли №1 и №3.
- [ ] Опрос Директа не жжёт баллы: интервал в минутах, один батч-отчёт на все кампании,
      бэкофф при исчерпании квоты.
- [ ] Офлайн-тест `tools/test_yandex_offline.py` проходит без сети и без токена.
- [ ] Write-операции проверены в песочнице до включения на живом кабинете.
- [ ] Авто-разгон бюджета по конверсиям Директа **не включён** (см. грабли №4).

## 9. Что НЕ надо делать

- Не переписывать движок правил, пейсинг и UI. Задача — адаптер за существующим интерфейсом.
- Не добавлять внешние зависимости (`requests`, `pandas` и т.п.). Только stdlib — это принцип проекта.
- Не строить выводы на данных Google Ads: аккаунт нестабилен/в бане, объёмы недостоверны.
- Не расширять периметр на Алматы без прямого указания владельца.
- Не вставлять вызовы LLM в путь принятия решения о расходе.
